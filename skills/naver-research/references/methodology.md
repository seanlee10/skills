# 비교·점수·일정 계산

## 비교 기간과 데이터 확인

기준 날짜는 요청이나 로컬 프로필의 계획 시간대를 사용한다. 기본은 Asia/Seoul이다.
조회 종료일은 오늘 진행 중인 날짜를 피하고, 응답의 `period`가 가리키는 주간 구간을 확인한다.
처음과 마지막의 불완전한 주는 계산에서 제외한다. 최근 4주와 직전 4주는 연속된 완결 주 8개로 구성한다.
주간 구간의 정렬·경계를 확인할 수 없으면 임의로 월요일 기준을 만들어 계산하지 않는다.
날짜 누락, 중복 주, 음수·비정상 ratio, 필터 불일치는 해당 비교의 미확인 사유다.
누락을 0으로 채우거나 서로 다른 주를 짝지어 비교하지 않는다.

최초에는 약 12개월의 주간 곡선을 조회한다. 작년 같은 시즌 또는 전년 동기 비교에 필요한 구간이
이 창에 포함되지 않으면 같은 키워드·기준 묶음으로 추가 기간을 조회한다.
12개월만으로 모든 작년 비교가 가능하다고 가정하지 않는다. 서로 다른 조회 창의 ratio 원값도 직접 비교하지 않는다.

## 기준 묶음으로 배치 연결

배치마다 기준 묶음 1개와 후보 최대 4개를 보낸다.
기준 검색어·기간·timeUnit·기기·성별·연령 조건을 모든 배치에서 동일하게 유지한다.
기준 묶음과 후보 묶음의 키워드가 완전히 같으면 기준 시리즈를 해당 후보에도 재사용할 수 있다.

동일하게 관측한 완결 주들의 집합을 `W`, 배치 `b`의 기준 ratio를 `a_b(t)`, 후보 ratio를 `x_b(t)`라 한다.
`W`는 모든 배치에 공통인 전체 비교 기간이며, 누락된 주를 배치마다 다르게 제거하지 않는다.

```text
C_b = mean(a_b(t), t in W)
z_b(t) = x_b(t) / C_b
관심도 = mean(z_b(t), 최근 완결 4주)
상승세 = mean(x_b(t), 최근 완결 4주) / mean(x_b(t), 직전 완결 4주)
```

이는 각 요청의 공통 배율을 기준 묶음으로 상쇄하는 비교 방식이다. 모든 배치의 같은 기준에 같은 기간을 사용해야 한다.
기준 묶음의 전체 기간 평균을 1로 본 배수이며 절대 검색량이나 시장 점유율이 아니다.
주마다 후보를 그 주의 기준값으로 나누면 기준 키워드의 계절성이 후보의 모양과 상승세를 바꿀 수 있어 사용하지 않는다.
상승세는 같은 배치의 후보 원시 시리즈에서 계산한다.

`C_b=0`이거나 기준이 대부분 반올림된 0이면 배치 간 비교는 불가능하다.
다른 공통 기준을 골라 모든 배치를 다시 조회하거나 관심도를 미확인으로 둔다. 임의의 epsilon으로 나누지 않는다.
직전 4주 평균이 0이면 상승세는 `계산 불가·기저값 0`이며 무한대나 임의의 최대 점수로 표시하지 않는다.
8개 완결 주가 없으면 상승세를 계산하지 않는다. API가 실제 반환한 0과 데이터 누락을 구분한다.

예를 들어 동일한 창의 기준 평균이 배치 A에서 10, 배치 B에서 5이고 후보 최근 평균이 각각 20, 10이면
두 후보의 관심도는 모두 2.0이다. 배치별 원값 20과 10을 비교해 A가 두 배라고 판단하면 안 된다.

## 작년 피크와 올해 시즌

작년 피크는 브리프에 맞는 지난 동일 시즌 안의 관측 최대 주와 실제 날짜로 기록한다.
동률이면 전체 피크 구간을 표시한다. 단일 이상 급등, 넓은 고원, 여러 시즌이 있으면 정확한 한 주를 확정하지 않는다.
올해 예상 피크는 별도 추정치다. 작년 날짜와 혼동하지 말고 추정 근거와 주 단위 오차를 적는다.
음력 명절·이동 행사·프로모션은 올해의 실제 행사 일정을 확인한다. 작년 날짜에 365일을 더하는 규칙을 쓰지 않는다.
근거가 한 시즌뿐이거나 검색어가 달라졌으면 계절성 판단의 신뢰도를 낮춘다.

이미 올해의 단일 연례 시즌이 끝난 주제는 다음 시즌 후보로 표시한다.
상시 주제·다중 피크·현재 재상승 주제는 종료된 한 번의 피크만 보고 내년으로 미루지 않는다.
피크 근거가 없으면 브리프 시즌 가설로만 표시하고 데이터가 입증한 시즌처럼 설명하지 않는다.

## 우선순위와 일정 실현 가능성

1. 예상 피크가 3주 이내이고 상승세가 1보다 큰 시즌 주제를 먼저 검토한다.
2. 같은 긴급도에서는 목표 시점에 발행 가능한 주제를 우선한다. 관심도와 상승세는 각각 근거로 제시한다.
3. 준비 시간이 충분한 다음 시즌 주제를 이어 배치한다.
4. 상시 주제는 주 1편 정도 끼워 넣는다. 메타 주제는 보유 측정 데이터의 재활용 근거로 선택한다.
5. 종료된 단일 연례 시즌은 다음 시즌으로 이연한다. 조회 실패 주제는 낮은 점수로 밀어내지 말고 미평가로 분리한다.

예상 피크 날짜를 `P`, 오늘을 `D`, 측정·작성 소요일을 `L`이라 한다. 기본 `L=14일`이며 실제 작업 여건에 맞게 조정한다.

```text
이상적인 발행 구간 = [P - 21일, P - 14일]
가장 빠른 발행일 = D + L
실현 가능한 권장 발행일 = max(P - 21일, D + L)
권장 측정 시작일 = 권장 발행일 - L
```

위 권장 발행일이 `P-14일`보다 늦으면 목표 구간을 달성할 수 없다.
`긴급·일정 재검토`로 표시하고 측정 시작을 과거로 잡지 않는다. 사용자가 소요 단축을 승인하거나 기존 측정 자료가 있어야
일정을 앞당길 수 있다. 가능한 가장 빠른 날짜는 참고안으로 적되 목표 달성 일정으로 표현하지 않는다.
측정 시작과 발행은 모두 오늘 또는 미래 날짜로 제안한다. 피크가 이미 지나면 다음 시즌이나 상시 활용 근거를 먼저 검토한다.

상시 글도 측정·작성 기간을 확보하고 같은 주에 여러 상시 글을 자동으로 넣지 않는다.
기존 목표 발행일과 충돌하면 사용자에게 변경안을 보여 주고 승인 전에는 유지한다.

## 쇼핑 보강과 재현 자료

분야별 쇼핑 데이터는 클릭 추이다. 분야는 요청당 최대 3개이며 카테고리와 검색어 묶음은 서로 다른 단위다.
카테고리 상승을 특정 제품의 매출 증가나 개별 키워드의 검색량 증가로 바꾸어 설명하지 않는다.
쇼핑 시리즈는 별도의 상대값이므로 검색어트렌드 점수에 합산하지 않는다.
선택한 분야 ID와 매핑 근거, 같은 기간의 최근·직전 추이를 설명 근거로만 보강한다.

로컬 분석 자료에 원본 응답, 요청 매개변수, 묶음 정의, 공통 완결 주, 계산값, 제외 사유, 조회 시각을 저장한다.
표에는 출처·기간·기준 묶음과 미확인 값을 표시한다. API 실패·비연결 상태에서 예시 숫자로 실제 순위를 만들지 않는다.
